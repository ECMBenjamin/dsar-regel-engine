        Execution Provenance & Audit Trail
        
                    
        Jedes Ereignis der Engine (bestätigte Fakten, Policy-Entscheidungen, Reviews, ausgeführte Aktionen) wird per SHA-256 verkettet. Erkennt nachträgliche Änderungen im Workflow. Das Log dient der internen Rechenschaftspflicht (Art. 5 Abs. 2 DSGVO); eine kryptografische Garantie gegen gezielte Manipulation des lokalen Speichers (z.B. per Dev-Tools) besteht vor dem Export jedoch nicht.
        

                    
        
                        RECHTLICHER HINWEIS ZUR AUDIT-GRENZE: Die Hash-Kette wird im Arbeitsspeicher des Browsers geführt und endet mit dem Export (.txt / .json). Sie ist nicht signiert und nicht extern verankert; wer Zugriff auf die laufende Seite hat, kann das Log samt Hashes neu berechnen. Sichern Sie den exportierten Record deshalb zeitnah in einem revisionssicheren System. Nachträgliche manuelle Änderungen am exportierten Text außerhalb dieser Anwendung liegen in der alleinigen Verantwortung und Rechenschaftspflicht (Art. 5 Abs. 2 DSGVO) des Bearbeiters.

        Die Engine liefert ihre Entscheidung nicht nur als Ampel, sondern als maschinenlesbares Objekt. Dieser Zustand wird bei jeder bestätigten Antwort neu berechnet und ist die Grundlage für jede Freigabe einer Aktion. Er enthält keine Inhaltsdaten der betroffenen Person (kein Name, kein E-Mail-Text, keine Datenkopie).

        Vision: Universal Rules Infrastructure
        
                    
        Die DSAR Regel-Engine ist die V1 einer Universal Rules Infrastructure: einer Schicht, die Regeln strikt von ihrer Durchsetzung trennt. Regeln liegen als versionierte Daten vor, eine generische Engine wertet sie deterministisch aus, und erst ihre Entscheidung gibt eine Aktion frei. Das Prinzip ist an den Open Policy Agent (OPA) angelehnt: Die Policy-Entscheidung ist von der Stelle entkoppelt, die sie durchsetzt.
        
                    
        Fachliches steckt ausschließlich in Domain Rule Packs. Die Engine selbst kennt keine DSGVO; sie kennt nur Regeln, Fakten, Risikofaktoren, Outcomes und Aktionen. Ein weiteres Rechtsgebiet ist damit ein weiteres Rulebook, kein neues Programm.
        
                    
        Diese Version enthält zwei Packs: Betroffenenanfragen (Art. 15, 17, 12 Abs. 3 DSGVO) und Datenpannen (Art. 33, 34 DSGVO). Das zweite Pack wurde hinzugefügt, ohne eine Zeile der Engine zu ändern; ein Test sichert das über einen Hash der Engine-Datei ab.
        

                    
        
                        
        01 · INPUTBestätigte Fakten
        Parser-Vorschläge werden erst durch Klick zu Fakten (Strict-Gate).
        
                        
        02 · POLICYRulebook
        Regeln, Abhängigkeiten, Quellen und Outcomes als Daten.
        
                        
        03 · DECISIONRules Engine
        PERMITTED, MANUAL_REVIEW oder BLOCKED. Default-Deny.
        
                        
        04 · ENFORCEMENTAction
        Das Antwortschreiben entsteht nur bei COMPLIANT oder REVIEW_COMPLETED.
        
                        
        05 · EVIDENCEAudit Trail
        Jeder Schritt in einer SHA-256-Hash-Kette.
        
                    
        
                
        

                
        
                    
        Die fünf Bausteine
        
                    
        
                        
        
                            
        1. Rulebook
        
                            
        Policy as Data. Jede Regel trägt ID, fachliche Frage, Risikofaktoren je Antwort, Rechtsquelle und Abhängigkeit (showIf). Eine Entscheidungstabelle (outcomes) ordnet Faktenlagen einer Aktion, Rechtsgrundlagen, Pflichtangaben und Auflagen zu.
        
                            
        In dieser Datei: DSARRulebook, BreachRulebook
        
                        
        
                        
        
                            
        2. Rules Engine
        
                            
        Lädt und validiert das Rulebook, prüft den Zustand gegen die Regeln, berechnet den Score und fällt die Entscheidung. Ohne vollständig bestätigte Fakten lautet sie immer BLOCKED.
        
                            
        In dieser Datei: UniversalRulesEngine
        
                        
        
                        
        
                            
        3. Provenance
        
                            
        Jede Regel verweist auf ihre Norm. Jede Entscheidung nennt die angewandten Regel-IDs, den Rulebook-Hash und einen Input-Hash. So ist nachvollziehbar, welche Regelversion auf welcher Faktenlage zu welchem Ergebnis geführt hat.
        
                            
        In dieser Datei: provenance, trace, inputHash
        
                        
        
                        
        
                            
        4. Verification
        
                            
        SHA-256 Self-Test beim Start, Strukturprüfung und eingebaute Testfälle jedes Rulebooks beim Laden, Hash-Kette über alle Ereignisse, Determinismus-Test und ein an Faktenlage und Vorgang gebundener Review-Sign-off. Ändert sich ein Fakt, verfällt die Freigabe. Die Kette erkennt nachträgliche Änderungen, ersetzt aber keine externe Signatur.
        
                            
        In dieser Datei: Tab „Audit Trail“
        
                        
        
                        
        
                            
        5. Interface
        
                            
        Die Entscheidung liegt als maschinenlesbarer Evaluation State vor. Dieselbe Struktur kann künftig über eine API oder das Model Context Protocol an KI-Agenten ausgeliefert werden.
        
                            
        In dieser Datei: Tab „Entwickler (API / MCP)“
